# Planning methodology

Read for substantial pre-build planning.

## Discovery

Capture the problem, target users, primary journey, desired outcome, functional requirements, non-functional constraints, deadline, budget, skills, deployment, integrations, and explicit exclusions. Mark supplied facts versus assumptions.

## MVP and scope

Choose the smallest end-to-end slice that proves user value. Put supporting capabilities in later milestones only when they depend on the slice or protect correctness, security, recovery, or launch readiness. If the requested scope cannot fit the constraints, explain the mismatch and reduce scope rather than hiding work in optimistic estimates.

## Requirements

- Functional requirements describe observable user or system behavior.
- Non-functional requirements describe measurable qualities such as latency, availability, privacy, recovery, or accessibility.
- Each important requirement needs an acceptance behavior and a proportionate check.

## Roadmap

Order milestones by user value, risk reduction, and dependency. Name prerequisites, deliverables, acceptance criteria, and what is deliberately deferred. Avoid horizontal setup phases that produce no useful behavior unless a safety or recovery prerequisite makes them necessary.
