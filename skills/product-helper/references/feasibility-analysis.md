# Feasibility analysis

Read when the requested scope, deadline, budget, or operational target may be unrealistic.

Assess product scope, technical complexity, developer experience, calendar time, integration dependencies, infrastructure and operations, budget, privacy or compliance obligations, and major failure risks. Distinguish build effort from launch and ongoing operating effort.

When the full request does not fit, preserve the core user outcome with a smaller MVP. State what is deferred, what assumption makes the estimate possible, and the signal that should trigger expansion. Never make a deadline appear feasible by omitting testing, deployment, recovery, or security work.
